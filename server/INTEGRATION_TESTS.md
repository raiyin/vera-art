# Интеграционные тесты

Интеграционные тесты находятся в пакете `internal/integration` и воспроизводят полный
пользовательский цикл «создание → редактирование → удаление» через реальный HTTP-стек:

- `works_test.go` — цикл для работ галереи (`POST/PUT/DELETE /works`, с картинками и материалами).
- `sales_test.go` — цикл для работ в магазине / art-store (`POST/PUT/DELETE /sales`, с картинкой, материалами и основами).
- `news_test.go` — цикл для новостей (`POST/PUT/DELETE /news`, с главной картинкой, галереей и видео).

Тесты поднимают полноценный боевой роутер (`router.NewRouter`) со всеми хендлерами,
сервисами, sqlite-репозиториями и файловым хранилищем, но на изолированных временных
данных (временная БД SQLite + временный каталог файлов). Авторизация выполняется как у
настоящего пользователя: через `POST /login` (заранее заведённый пользователь с ролью `admin`).

После каждого HTTP-запроса тест проверяет не только HTTP-ответ, но и фактическое состояние
базы данных (и файлов на диске), т.е. то, что данные действительно появились, изменились
или удалились.

## Требования

- Go 1.23+.
- Драйвер SQLite `mattn/go-sqlite3` требует CGO: сборка и запуск должны выполняться с
  `CGO_ENABLED=1` (обычно включено по умолчанию).
- Файлы-фикстуры (опционально): `test_data/1.webp`, `test_data/2.webp`, `test_data/3.webp`,
  `test_data/sample-5s.mp4` в корне репозитория. Если их нет, тесты используют встроенный
  минимальный PNG — на корректность тестов это не влияет.

## Запуск

Из каталога `server/`:

```sh
go test ./internal/integration/... -count=1 -v
```

Полный прогон всех тестов проекта:

```sh
go test ./... -count=1
```

## Что именно проверяется

| Сущность | Создание | Редактирование | Удаление |
| --- | --- | --- | --- |
| Работа (`/works`) | все поля + 2 изображения в БД и на диске, материалы `[1,2]` | все поля, новое изображение (`1,2,3`), материалы `[3]` | строка и связи `works_materials` удалены |
| Продажа (`/sales`) | все поля + изображение, материалы и основы в БД | поля, замена изображения (старый файл удалён) | строка, связи и файл изображения удалены |
| Новость (`/news`) | `data`-JSON + главная картинка, галерея, видео; сгенерированные `id`/`dir` | тексты изменены, медиа-списки сохранены | строка удалена, каталог новости удалён |

## Известные особенности приложения, учтённые в тестах

- **Пути файлов.** Сервис галереи и новостей получает «абсолютный» каталог (в проде это
  `client/public`), а `Dir`/`work_path` уже содержат префикс `/content/...`, поэтому файлы
  физически сохраняются с повторением префикса внутри каталога. Тесты используют ровно эти
  пути, как в продакшене.
